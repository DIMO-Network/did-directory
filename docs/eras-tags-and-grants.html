DIMO 3.0 · identity & permissions

Eras, Tags and Grants

One rental car, six parties who need access to it. How we grant that without signing as the car, and without one grant per car per partner.

The move

From one NFT grant per car to one grant per relationship

Today a permission is an on-chain record. The owner's smart account signs a SACD document, we pin it to IPFS, and a PermissionRecord lands on Polygon against one Vehicle ID NFT. For one person with one car that is the right shape.

A rental fleet pays for it once per car, per partner, in gas and in bookkeeping. Their whole fleet is also readable on a block explorer.

We keep the two-tier token flow. The grant itself moves off-chain: the controller of record signs, and it points at a tag, a named set of cars that changes over time.

Where things live

Public identity, private relationships

The directory holds what has to be globally verifiable: the car's keys and its control history.

Everything that shows commercial structure stays in the org's own store. Who controls what, which cars are grouped, who works for whom. A competitor reading the chain today gets all three for free.

The link between the two is a commitment: sha256(controllerDID ‖ era ‖ salt). Anyone can see the car has a controller. Only someone holding the salt can show who it is.

Time

Two clocks: when a grant works, and which data it reaches

Every grant separates validity, when it can be used, from the data window, which timestamps it can read. Coverage is the overlap of all four. The answer is a set of intervals, not one range.

Delegation

Every hop can only narrow

Control, liens, consent, partner agreements, sub-orgs, device pairing: same record. A grant with no parent is a root, and it is only valid if the issuer can open that car's commitment. Everything below it has to be a subset.

At request time

The issuer does the work once; the data services check one token

Chains, tags, openings and revocation windows all get resolved when the token is minted. dq and fetch never walk a chain. They match a subject and clamp the query to the windows in the token.

Open thread · permissions format

Fixed choices say ODRL with a DIMO profile. What is built uses a plain record. Proposal: ODRL is the wire format, the record is the parsed form. assigner and assignee map to from and to, target (an AssetCollection) to a tag, action to abilities, dateTime constraints to validity. ODRL duties carry what code can't enforce: retention, refunds, Stripe.

Open thread · device data as a grant

A device writing data is a grant to the device DID. That works today, except the evaluator treats telemetry:write as historical and checks it against data timestamps instead of request time. One line fix in the ability classifier.

Decided

Liens irrevocable for fleets only, consumer loans revocable by either side. Controller links are hash commitments, not plain pointers. Countersigning optional, required only where contract terms are attached. Approval above 500 vehicles. Renters stay out of the protocol for v1.
